# Incremental features

Drop each new feature, app version or experiment into this folder as **its own sub-folder**. It is registered
automatically:

1. The folder gets the next number (`INC-0NN`) in [registry.json](registry.json).
2. An entry is added at the top of [CHANGELOG.md](../CHANGELOG.md).
3. A row is added to the index below.

If a folder is removed, it is marked *removed* and logged. If the same folder is added again later, it is
registered again under a new number.

## How the registration runs

| When | What to do |
|---|---|
| Before every `git commit` | Nothing: the pre-commit hook in `.githooks/` runs the tracker and stages the updated files. |
| Right away, while you work | `node tools/track-features.mjs --watch` (keeps running; reacts within 2 seconds of a folder change). |
| By hand | `node tools/track-features.mjs` |
| Check only (e.g. CI) | `node tools/track-features.mjs --check` (exit code 1 when a folder is not registered yet) |

The hook is switched on once per clone with `git config core.hooksPath .githooks`.

## Describing a feature

Copy [_TEMPLATE/FEATURE.md](_TEMPLATE/FEATURE.md) into the new folder and fill it in. The first heading becomes
the title and the first paragraph the summary. Without a `FEATURE.md` the tracker uses the folder's first
`README.md` (up to two levels deep). Folders whose name starts with `_` or `.` are ignored.
